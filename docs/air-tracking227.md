# 227空投弹幕追踪审计与姐姐战时长目标 · 2026-10-30

用户明确：飞机区域投递/剑雨散落感要保留；装备眼保健操后，投出的弹幕应继承主角追踪。不要将修正方向擅自改为所有投弹集中锁死同一目标。本轮只审计和诊断，未改战斗逻辑或数值。

## 实现证据

146 snapshot_packet146先经现有发射路径收集伤害、速度、角度、寿命、蓄力、穿透、音符、水柱、分裂和tracking等载荷；投递时emit_packet146再建立同一池里的弹丸并写tracking146。不是每只敌人重新适配一套武器伤害，但也不是可保证未来所有字段自动继承的完整通用攻击描述。

实际NativeCombat113读取的是buffs.level(eye_exercise)，不读取每颗shot.tracking146；脚本113路径也按当前全局buff控制。保持装备不变时不等于追踪完全未开启，但载荷字段不是运行权威来源。C中途换装会清弹，所以诊断改变全局与快照的不一致不直接等于普通流程会遇到换装在途问题。

更直接的问题：native与113脚本转向都先检查XZ速度；纯垂直速度返回不追踪。近乎向下时以XZ夹角判断搜索锥，目标即使只在下降方向旁边，也可能因相对于极小水平分量的夹角被拒绝。追踪目标使用enemy.position + Y.65，而蝙蝠代理的position本身已跟在hit_area中心附近，会额外向上拉；应该统一使用明确的命中/追踪锚点。

152还有随机九发模式关闭追踪的历史分支，但scatter152默认false，当前manager是辅助六连投；不能将这个分支当成当前已经开启的原因。

## 最小实际原生探针

probe_air_tracking227.gd加载现有DLL，6种输入全部观测成立（air-tracking227-probe.json）：

- 纯下落(0,-6,0)，目标位于下方侧面：有眼也不转向。
- 近垂直(.1,-6,0)，下方目标仅向水平另一侧偏.5：仍不转向。
- 普通水平弹对斜侧目标：正常转向，控制组有效。
- packet tracking=1/global eye=0：不转；packet tracking=0/global eye=1：转，确认运行数据来源。
- 弹丸与蝙蝠中心等高、正对中心：转向后却抬高Y，复现额外.65m目标高度。

这是最小原生算法输入复现，不是完整森林空投命中率对照；没有声称已确定这几个问题各自造成了多少实战伤害损失。尚未修复DLL或脚本追踪，也没有改投递分配。

## 后续修复方向

保留区域采样与多颗独立散落弹。投出后用发射时的载荷属性进入共用弹幕更新，空中发射的目标搜索/转向应考虑完整3D方向、实际命中锚点，保留眼保健操有限转向速度、寿命与场景碰撞。无眼仍是原散射，下落追踪不等于飞机本体/每颗弹丸必命中。原生和脚本回退需同义验证，避免只修一条实际未使用的脚本。先修继承/转向再评估飞机强度，撤回此前优先集中蝙蝠投递的建议。

## 时长建议（尚未确认、未落数值）

针对第一地区压轴姐姐战，建议以常规合适组合成功战斗60—90秒、2—3次修补为初始设计目标；熟练强势/主动爆发允许约30—45秒、1—2次，更极限可以更短。这是本项目调参建议，不是RPG通用标准。现有常驻多鹅眼/手电/弹弓普遍一窗、约11—22秒，不足以展开第二修补蜘蛛等循环，不应因倍率符合代码就视为整体合理。

单窗击倒可以是少数主动爆发/充分准备的收益，但不宜成为普通常驻输出的默认。修复飞机后选代表组合，按实际输出与目标阶段时间反推猫/蝙蝠血量及爆发预算。当前一轮已有损失8—10/14血的样本，直接把血量倍增到三轮会同步放大消耗，必须连同攻击密度、输出机会和喘息一起评估。当前不改猫HP、蝙蝠HP、修补时长或装备成本。
