# 229眼保健操与手电红灯试验 · 2026-10-30

## 本轮决定

眼保健操一级射速50%→25%，仍2槽，追踪强度不改；第二份射速合计50%（4槽），保留二级追踪。手电采用用户提出的低血固定一档方案：生命严格低于上限1/3且>0时，伤害固定+35%，不提高射频，不随剩余血继续增加。在14决心预览中4血或1血同档，5血和恰好14/3血不触发。35%是试验值。未加入能量/计时消耗。

## 实现范围

新world229继承228两段节奏，默认仍猫100/蝙蝠80，14决心/6槽。新buff_book229保留原多鹅40%权重、主角时刻倍率及数学作用域，单独替换眼射速曲线。新memory_kit229只覆盖对应碎片说明，C仍由profile226按2槽校验。

手电直射、载荷快照（水柱飞机/笔记）、旧巡航147射频入口统一经过flashlight_damage_gain110/flashlight_rate_gain110钩子。默认实现完全保留旧连续低血双乘规则，229分别返回1或1.35、恒1。发射时的载荷仍快照伤害/射频，不给已经在途的旧载荷追加一次红灯增幅。没有修改原生DLL、弹幕命中、目标分配、费用或Boss状态机。

红灯为血条左侧的小HUD提示，1.25Hz缓慢脉冲，只有装备手电且满足门槛时显示；暂停冻结，回血越过门槛/卸装/结束/重开立即清除。它是UI，不是世界实体，没有碰撞、投影、发光灯或主角几何变更；不加满屏闪红。来源为red_timer229.gd程序化圆形绘制，无新增位图。截图balance229-red-lamp.png已检查。

采样新增balance229参数及红灯/主角时刻覆盖秒数；每个修补窗保存开始HP、red_seconds和stage_seconds，用于区分主动有没有覆盖窗口。未改用户过去的采样。

配置独立boss_balance229.cfg/plush_boss229_preview.cfg，首次只继承228（没有则226）的碎片，HP使用229试验默认100/80。旧228菜单20、227菜单19保留，新latest229；启动器保留UTF-8 BOM并通过powershell.exe list校验。

## 尚未实现的设计讨论

三分钟计时对目前几十秒的Boss约束较弱；若未来采用能量，应作为连续照射消耗、停火恢复的独立武器节奏设计，不能仅在现有收益上再叠一个无关紧要的长计时。本轮先验证固定红灯。

纸飞机不采用小体型目标额外倍率。可进一步讨论收放投递范围：大圈覆盖/小圈集中，弹数与总伤害不变，落弹仍随机直落，以覆盖面积换集中度。需要同时保留局部落点修正、正确命中锚点，并验证短窗启动和双目标分摊的预算；收圈能否将六七窗压到合理轮数必须实测。该方案尚未接入，本轮也没有恢复下落转向或改成自动集中投递。削眼也影响剑雨，本版不是宣称已完成其平衡。
