# 66 林间视野 · 2026-10-19

用户授权试作局部树冠让开，并增加帧率显示，以观察掉帧情境。

入口仍为play.cmd / preview_world_garden.cmd，主场景world66，普通入口树根近景。Compatibility、25°俯视/42°FOV、原景深、水波/波光、65根部碰撞及行走优化继续沿用。

## 试玩

- **Alt+O**：局部让开（默认）／旧整树淡出对照。
- **F**：遮挡让开总开关。
- **Ctrl+F9**：性能面板显隐，独立于F1说明面板。
- **Ctrl+F10**：清空性能面板历史；建议到目标地点后清零再观察。
- **Ctrl+F4** 林路、**Ctrl+F8** 树根、**Ctrl+F6** 湖桥、**F3** 小屋。

## 遮挡处理

canopy_occlusion66由world66的旧遮挡回调驱动，避免新旧方案同时运行。每70ms检查45m内可见树，按精灵纹理实际尺寸、offset、pixel_size、global_transform投影四角边界，再用相机到角色的射线与贴片平面判断该树是否处于角色前方。保护区域覆盖身体，而非只检查头部一点。

窗口以身体为中心，行走时朝前最多偏移约0.6m；前移偏置指数平滑，停止时慢慢回中。尺寸随角色屏幕高度和视口比例调整，缩放时不会固定成错误大小。候选进入边界留10px、退出边界放到36px，离开后保持约0.35s，再约0.625s收回；展开约0.22s。传送超过3m立即清除原地状态，避免旧位置残留开窗。

canopy_window66保持与原风动树相同的光照、风动和不透明绘制路径。只裁出角色附近的椭圆区域，窄环边缘采用固定在原贴图像素上的4×4有序覆盖，再沿用场景景深；没有逐帧随机、没有滚动边缘噪声。窗口不是整树半透明，外围树冠和地面的细节不会大面积叠加。根片继续实心绘制，独立树影、物理碰撞不受窗口影响。

试作中发现普通ALPHA透明会让活动树绕过已有屏幕景深处理，导致外围树冠突然变清晰。已移除这条路径，最终实景冻结对照中，窗口外采样变化0。关于透明材质与屏幕/深度纹理的限制，参见[Godot空间着色器说明](https://docs.godotengine.org/en/4.6/tutorials/shaders/shader_reference/spatial_shader.html)。

这是第一版视觉对照：极密的多层树冠下仍会呈现明确的椭圆开口，边缘是很窄的像素覆盖带。是否需要扩大、缩小或改为更不规则的叶缘，应根据实际走动观感决定；不通过快速噪声动画掩盖边界。

## 帧率面板

frame_overlay66独立CanvasLayer，位置左上（避开生命条），F1隐藏说明后仍在。旧25性能文字隐藏，避免两套FPS同时出现。

- FPS / ms每帧：按最近约1秒的墙钟帧间隔平均，文字每0.25秒刷新。
- 近10秒最慢ms：单次长帧会暂时保留，不会被一秒平均吞掉。
- >33ms帧数：最近10秒超33.3ms的帧数，约对应单帧低于30FPS的明显长帧。
- 最近慢帧：最近一次>33.3ms事件的耗时、附近区域、XZ坐标和游戏时刻，保留至下次事件或清零。

60FPS约16.7ms、30FPS约33.3ms。这里测的是实际帧间隔，包含等待渲染/呈现等时间，并非单独GPU耗时或CPU耗时，不能只凭这一个数断定瓶颈。样本使用固定4096槽环形数组，4Hz聚合，无逐帧文件写入；切后台暂停采样，切回清除上一次时间戳，避免把后台等待记成卡顿。

## 验证

canopy66_probe.gd：13项通过。覆盖动态水/根碰撞保留、渲染器/镜头、真实近景树开启、整树fade保持1、窗口可见、外围不变、出入缓冲、恢复、旧版对照、短慢帧保留与位置、F1独立显示、清零。

冻结实景每3像素采样一次，窗口内7609个像素发生明显变化，窗口外0；比较时已换算1600×1000逻辑视口与1440×900实际截图的比例。慢帧统计使用受控58ms样本验证，canopy66_monitor.png是该测试截图，不是实际性能结果。canopy66_live_monitor.png是清零后真实运行采样截图。

另做360帧行走短测：中位11.460ms，P95 16.911ms，最大20.208ms，无>33.3ms帧。该数字仅表示本次测试状态，不保证所有地点、战斗、长时间运行都如此，也不是与65同时交替采样的严格性能对比。

结果：canopy66-validation.json、canopy66-performance.json。截图在captures/world_restart/canopy66_{solid,local,legacy,monitor,live_monitor}.png，已人工检查最终local与live_monitor。
