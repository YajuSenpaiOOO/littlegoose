# 270 花与团团整体合成

用户指出花独立悬浮、身体滚动而花不动，明确要求程序化将花和身体合成同一帧。本轮采用Godot Image运行时alpha合成，不生成/覆盖原PNG，也不使用AI重画。修复共用268蓝花与269玫瑰花；270是269同玩法的新入口。旧268/269也共享此次显示修复，不把它们误称保留旧悬浮花表现的视觉对照。

## 合成与锚点

flower_composite270按原素材/姿态元数据/花种缓存。每个实际姿态（含待机、蓄力、跳起、落地、受击、倒地和现有额外姿态）用源alpha范围定位头顶，在头发上沿下方12%高度处重叠花的原挂点，横偏.12m，按flower.scale/body.scale换算，最近邻缩放花；先body后flower做透明合成。此为现有素材的程序化装配，未重画造型。

裁掉源素材无效透明边，再以原身体旋转中心为基准计算组合轮廓四角的最大半径，扩成足够完整一圈旋转的透明画布。只平移每姿态foot像素坐标，保留原scale/visible_width/visible_height，即身体世界尺寸、脚锚点、软体归一化跨度与原滚动圆心不变。花不改变胶囊或伤害面积。缓存返回独立姿态字典/纹理集，不修改世界共用原姿态与纹理，普通团团与休息Boss不被染花。缓存只在首次花种/姿态集合初始化合成，非每帧CPU拼图。

移除268/269的独立花Sprite创建和单独倾斜；身体与花由同一visual/同一soft_ink一次绘制，共同经历原旋转、压扁、命中染色、凹陷、头部延迟、朝向翻转及倒地。269蓄力轻抖/晕时摇身也作用整张图。保留既有竖直角色平面、脚点、原统一影子路径与受光政策，不改光照、树或主角几何。花随整图纳入当前visual投影来源。
