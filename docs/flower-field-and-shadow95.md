# 95 一片林隙花海、统一受影与周边更新

2026-10-20。默认world95，旧94保留。运行play.cmd或preview_woodland95.cmd；Ctrl+Alt+F2到花海，Ctrl+7西侧、Ctrl+8后林，Alt+1/2/3/4切时段。

## 花海与光影

将94分散在四处的182株花，改为一片空地内的454株。相对林地中心(-3.1,-5.7)，外轮廓约11.6×6.8m，避开树干、岩石和原路，边缘逐渐变稀。白花为主、少量蓝紫和淡黄，仍使用独立裸花茎MultiMesh；周围草来自原草组件，没有附带草裙，无新增硬碰撞。

查出100簇灌木/蕨草、花与12块手绘苔岩使用的材质含shadows_disabled，因此原生树影无法落在表面。该标记关闭的是接收阴影，和GeometryInstance的投射开关不同，参见[Godot官方材质说明](https://docs.godotengine.org/en/4.7/tutorials/shaders/shader_reference/spatial_shader.html#render-modes)。95专用材质移除此标记；灌木/花同时启用投射，岩石继续用已有63贴地投影，避免重复叠加。保留94碰触、风摆、原林荫/昼夜色调。

用临时仅投影的盒子对蕨草与岩石做受影开/关截图，按素材不透明区域映射到真实截图坐标统计暗化，验证实际画面变化，未只检查开关值。蕨叶与邻近植物存在遮挡，所以不假定所有源纹理采样点都可见。盒子仅在探针存在，游戏不生成。测试截图woodland95_fern_*、woodland95_rock_*。

## 当前全图效果的实际范围

| 系统 | 原有行为 | 95处理 |
|---|---|---|
| 原生太阳阴影 | 最大距离70m；普通树影组件72m可见距离，引擎另做视锥/光源裁剪 | 保持质量与距离 |
| 草 | 分块MultiMesh，46m显示范围，Shader按主角/足迹局部响应 | 保留 |
| 飘尘 | 固定96粒子池，主角附近重生，13–20m淡出 | 保留 |
| 萤火虫 | 固定32粒子池，14–19m淡出，远于20m重生，白天关闭显示 | 保留 |
| 灌木/蕨草交互 | 100簇原本逐帧算碰触并上传参数 | 缓冲视野外停止碰触与风摆参数更新，进范围后恢复；不重建对象 |
| 自定义63落地投影 | 共14个节点各自逐帧检查；缓存键变化会重建贴地网格 | 集中调度，缓冲视野外不更新/不画；每帧最多更新2个 |
| 景深等后处理 | 当前视口的屏幕像素成本 | 无法用“地图远处对象停算”直接省掉，保持原效果 |

自定义范围是镜头每边外扩25%，再加素材半径与地势余量。同时检查物体脚、顶部、影子端点和中点，保留镜头外投射进画面的影子。每0.12秒刷新候选；网格常驻，没有走到边界才加载/销毁资源。全图预览review72不受范围限制。

额外手动筛树影的试验中，可用候选454→约110，但绘制次数仅1020→1018；说明原生渲染器已有实质裁剪，该试验未保留。最终新增范围调度只作用于自定义投影和林下植物交互，未关闭全图物理、碰撞、敌人或远景物体。

## 检查与测量边界

woodland95_probe.gd有10项检查：集中花海、落点范围、受影与投射配置、蕨草/岩石真实截图暗化、远处自定义投影停止、接近恢复、原入口实走及穿过花海。woodland95_scope_probe.gd另做花海/西侧/后林/车站四个镜头的范围开关比较：冻结场景动态，对明显颜色差异计数，四处changed_ratio均0（通道差总和阈值0.06），未出现可见影子丢失。结果在woodland95-validation.json与woodland95-scope-validation.json。

性能探针请求2560×1494窗口，本机实际截图2390×1494（窗口宽度受桌面限制），关闭垂直同步与FPS上限，每档180帧并预热，范围开关采用先后/反序两组。分别临时关闭太阳阴影和景深作诊断，结束恢复。景深需用time55.focus_mode86控制，否则昼夜控制器会覆盖直接写入的radius_pixels；最终探针采用该模式开关。TIME_PROCESS监视器是低频统计，不能将其短样本值当作每帧CPU分析。

这类短时静止样本只能比较当前镜头成本，不能据此宣称修复用户的偶发卡顿或持续掉帧。范围限制没有稳定的大幅提速证据，原生阴影有可测开销，但其开销并不等于全图所有影子都在渲染。实战、持续移动和不同分辨率仍可能呈现不同瓶颈。
