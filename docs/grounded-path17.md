# 17：坡面树根、斜摆件投影和土径边界

入口沿用根目录 `preview_front_cottages.cmd`，现在打开 `scenes/sandbox/grounded_path17.tscn`；16场景单独保留。默认选定1号青灰石板房，2号轻像素环境、25°透视和既有移动方式不变。

## 树根断口

15/16把树干按水平UV线截断，却把根条上沿逐点贴到起伏地形；此前仅测试底边贴地，漏测了两块图像在坡上的接缝。因此平地正常，坡面出现水平裂口。单纯把根条上沿拉回同一高度也不够，坡面仍可能吞掉中段。

17将树干最下方约8%高度并入过渡网格，顶部与立牌的截线完全相同；中间从直立树干渐变到实际地形，外侧根须沿坡。树干与根条使用相同场景光照和绘制材质，保留向地面投影；关闭树卡接收纸片投影，以免自己的立牌影子在弯折根条上形成一道假暗线。这也意味着树卡之间不再互收实时投影；体积暗部主要来自原画，地面与草仍接收树影。不是把根条顶点全强制铺平，也没有把整块地形改平。

## 斜摆件

16的小接触斑点跟到了脚点，但普通方盒体覆盖了不同深度的脚，不能还原斜摆件的投影。17用原图alpha轮廓做影子网格，沿图片横向各列补出支撑深度；镜头射线穿过原图脚点，与真实地形三角面相交，逐列把脚放到地面。网格只投影，不作为可见建模替代原画。木柴、长椅、矮墙的普通方盒投影停用。

可以继续使用略带侧面的摆件，重点是给每张图标出前后脚和侧角的占地关系；不能用一张通用影子矩形通吃。当前做法适合固定25°、固定朝向的立牌镜头，图片里的侧向角度仍然画死；若将来允许绕物体旋转镜头，仍需多朝向贴图或完整几何。未把限制简化成只能生成正面或背面。

足点平面读取实际物理地形，初始化碰撞未同步时才回退二分求交。镜头不变时不重算；改变时按列缓存深度系数。当前4件摆件的完整接地/影子更新在本机单独测量约1.8ms（非整场景帧率或大量摆件压力测试）。全地图扩产之前仍需分区、可见性筛选和影子网格缓存，不能据此推断无限扩展的开销。

## 土径小样

J对照新土径与旧模糊边。新路面为原生地面shader：暖棕压实土色、低对比颗粒/少量细石、不规则小块边界、很窄的过渡；另补少量较矮的可拨草跨过路边，与原草共用一个MultiMesh，路径中心不刷草。不是另贴一张含草的全景道路图。

这是确定路面和衔接方式的第一版，不是最终土径美术。应在同一小段里同时定土的明度/颗粒、道路宽窄磨损、草皮断边以及少量立体草侵入；只画漂亮的道路内部、边界仍旧模糊，问题不会消失。认可后再决定是否需要专门生成可重复土质贴图，替换当前程序颗粒。没有为这一轮重新抽房屋/树木资源。

## 检查与对照

`scripts/grounded_path17_probe.gd`：17项实际OpenGL检查，包括123棵树的顶部接缝/根须外沿、确有跨坡高差、平地切换回归、草仍在同一批且避开路中心、三个观察位置的脚点落地与屏幕对应、实际GPU投影变化/恢复、J路面变化/恢复、V和P隐藏行为。脚点由投影网格本身求出，不仅检查脚旁的软影。

截图 `docs/captures/world_restart/ground17_mid.png`（坡面/道路）与 `ground17_props.png`（木柴/矮墙近景）已人工核对。可带 `--view=mid`、`--view=props`、`--view=forest` 运行场景，既有 `--capture=绝对路径` 可复现。
