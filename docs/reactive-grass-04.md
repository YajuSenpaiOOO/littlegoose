# 草地对照 04：细节底图与可穿行植被

2026-10-16。用户对两版地皮仍在取舍，更喜欢旧版的材质细节，希望地表草像老灌木一样有体积、能穿梭/回应脚步，并询问性能。本轮暂停扩产树，不生成新图片；先做可运行的公平对照。

## 查看与对照

根目录 preview_world_grass.cmd 直接进入小屋外草丛，WASD 移动，滚轮缩放。5 可从其他区域返回试走区。

- 默认：旧版细节地皮 + 03 暖日日光 + 420 簇立体草/灌木。
- P 只切换旧细节地皮/03 简化地皮；人物、树、草的分布、相机与光照不变。修正 03 中同时切光照导致难以单独比较地皮的问题。
- G 单独开关立体植被，P/G 可以组合比较四种画面。
- N 仍可切天色；树根 H、滚轮、总览和移动插值保留。

地皮选择仍未锁定。当前建议继续试“旧版材质细节 + 更清亮日光 + 有疏密的立体植被”，没有宣称刷草能弥补所有底图风格差异。六棵新树只是已有对照，不继续按未确定方向扩产。

## 草的表现

沿小屋院外和连接路边安排九个成簇试验点，共 420 个实例。大部分是原 exterior 图集末行的草簇，约八分之一使用旧 departure 的 understory_bed_v2.png 缩成低矮灌木组。原素材未改图、未新增生成资产。排除门前石板、已有物件的实心脚印以及道路中心。

每簇以根部落点作为 Sprite2D 的排序位置，加入与人物同一个 Y 排序父节点，所以可以前后穿行并遮住部分脚部。没有碰撞、没有减速，也不为每株增加太阳投影或局部灯光。

同一个材质在顶点着色器里进行轻微摆动、人物靠近时侧弯/压低，脚步经过后短暂回摆再恢复。控制器每帧只更新共享位置、时钟和八个有限脚步记录；草实例没有单独脚本。G 关闭时同时隐藏实例并关闭控制器更新。跨区域跳转时清空过远的脚步记录，避免从旧位置拖出长轨迹。

这是互动机制和地表选择试验，现有贴图/植株混用还不是正式草的美术。不能把整张地图铺成同样高度和密度的草毯：底层短草/苔土保留贴地材质，近景草丛分组穿行，中层灌木负责围合，路面与战斗中心留白。后续按区域做疏密及远近分级。

## 性能实测

Godot 4.7.2，GL Compatibility，本机 RTX 5060 Laptop GPU。使用同一脚本、同一路线、相同镜头和旧地皮/暖日，关闭 VSync/FPS 限制。每组分别运行，预热 1 秒，沿小屋路线继续移动采样 5 秒。使用固定时间而不是固定帧数，避免不同帧率走过不同长度的路线。

| 立体植被实例数 | 帧间隔中位数 ms | p95 ms | p99 ms | 最大 ms | 超 25ms |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 0 | 2.676 | 3.870 | 4.461 | 6.551 | 0 |
| 420（默认） | 3.423 | 4.990 | 5.337 | 9.691 | 0 |
| 1680（4 倍密度） | 5.519 | 10.121 | 10.815 | 12.542 | 0 |

默认密度相对空草地样本 p95 增加约 1.12ms，说明有可测开销，当前本机试验区仍有余量。不能把它外推为全地图/低配机器/正式战斗的帧率保证；样本没有敌人、弹幕或长时间运行。高密度透明叠画和大量排序节点依然会增加成本，扩图时只让近景/需要交互的区域承担高密度植被。

原始记录：captures/world_restart/grass04_perf_0.json、grass04_perf_420.json、grass04_perf_1680.json。早先固定帧数的临时样本不用于这个表格。

复现：使用 scripts/world_motion_benchmark.gd，附加 `--uncapped --duration=5 --grass-count=420 --report=res://docs/captures/world_restart/grass04_perf_420.json`，把 count 改成 0/1680 可复测其他组。

实现参考：[Godot 4.7 2D batching 与材质复用](https://docs.godotengine.org/en/4.7/tutorials/performance/gpu_optimization.html)、[CanvasItem 顶点着色器](https://docs.godotengine.org/en/4.7/tutorials/shaders/shader_reference/canvas_item_shader.html)。共享材质仅是减少状态开销的做法，不代表所有实例必然合成一个 draw call。
