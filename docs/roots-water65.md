# 65 银柳与流水 · 2026-10-19

用户要求恢复动态水面、解决粗树根穿行，并反馈行走帧率偏低；近景树隐去作为讨论项。

入口仍为根目录play.cmd / preview_world_garden.cmd，主场景world65。Ctrl+F8近看树根，Ctrl+F6去桥，Alt+M/G切换水波/波光。保留64树下小景和63环路、原车站高度、Compatibility及25°/42°镜头。

## 水面

bridge_lake65继承62，恢复60已有的motion60与sparkle60。保持绳桥、绘本水和降低后的水位；未增加反射相机、灯源或粒子。61远水柔光仍默认关闭，其视觉尚未获得认可。

## 树根碰撞与复用

root_collision65继承willow_clearing64。在_apply_tree后读取当前纹理下部alpha，按同一foot/pixel_size/drop和25°根片折叠投影得到地面XZ轮廓。每约0.55m横向切段做凸包并向上挤出0.85m、向下0.12m，形成StaticBody3D/ConvexPolygonShape3D；默认银柳22段，原圆柱树干继续兜底。

这是一组不可穿越的地面障碍，不是可攀爬的根部表面。细碎根纹理不做逐像素碰撞；凸包近似会填补每个窄段内的小缺口。换树时自动重建，旧占位树对照关闭新增根碰撞，恢复银柳重新启用。无需人工围栏；将来很低、允许踩过的细根可另外指定为装饰，粗根继续阻挡。

## 移动性能

发现旧版家具接地在相机位置变化时重建ArrayMesh并反复做地面查询。world65允许普通微移最多每50ms重建一次；移动超过0.3m、相机旋转、地形/接地开关或FOV变化会立即刷新。保留已生成网格，游戏绘制和物理仍按原帧率运行。树材质保留风/透明状态缓存，只有状态或实际shader改变才重新套用灯光shader。

## 近景遮挡讨论：尚未更换视觉方案

现有forest_cottage13每帧用树根Z方向、height*0.43粗宽度和角色头部单点判断；没有退出缓冲。整棵树的fade最低0.25，在透明shader里又平方为约6.25%不透明，边界往返容易让整片前景显隐；多层树冠与地表细节同时透出也容易杂乱。不要误归因为当前一直采用随机抖动：旧逻辑淡出时实际上切到了透明shader。

建议下一轮先做小范围对照：屏幕上保护角色身体与前方短走廊，按实际精灵尺寸及深度判断；提前进入、扩大退出范围、离开后短暂延迟恢复；必要时改为角色附近稳定柔边开窗，保留外围树冠框景。最贴相机的一层可单独作为低对比、缓慢淡去的前景层。暂不增加快速滚动噪声或大面积幽灵半透明。

参考：[Rangefinder开发者的树木开窗案例](https://www.reddit.com/r/gamemaker/comments/1vmw1um/i_created_a_see_through_shader_in_gamemaker_for/)。开发者也反馈过树叶与地表同时细致时，整树透明/抖动会显杂乱；其动态噪声开窗仍有观感争议，适合借鉴局部让开思路，不宜照搬边缘动画。商业作品可从[TUNIC官方画面](https://tunicgame.com/)观察固定视角下的前景构图，不据此推断其内部遮挡算法。

## 验证

roots_water65_probe.gd：9项通过，覆盖动态水状态、分段碰撞数量、全部根段射线阻挡、实际主角胶囊扫掠、外围通路、换树更新/旧树关闭、木凳旁实际行走。胶囊扫掠临时仅查询障碍层，以排除坡地先被命中的影响，随后恢复正常mask=3；实际行走使用正常物理。
