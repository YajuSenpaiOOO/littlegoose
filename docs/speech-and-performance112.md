## 性能实测：尚未优化到 120 FPS

同一台 RTX 5060 Laptop，GL Compatibility/Jolt，2560×1494，关闭垂直同步；七只普通／精英／大王持续 AI，测试用高血量，固定卡组。每阶段先稳定 30 帧，再取 240 个显示帧。诊断基线为 world111；112 的气泡功能不修改原战斗仿真和画面设置。

| 阶段 | 帧耗时中位数 | GPU 绘制中位数 | P95 |
| --- | ---: | ---: | ---: |
| 七敌人，不开火 | 18.38 ms | 3.12 ms | 31.36 ms |
| 六卡持续开火：四鹅、追踪Ⅱ、分裂Ⅱ | 37.90 ms | 3.21 ms | 53.51 ms |
| 上述实射，分辨率改 1280×747 | 41.56 ms | 1.70 ms | 55.20 ms |
| 暂停世界节点更新，保留完整场景绘制 | 3.37 ms | 3.36 ms | 5.20 ms |
| 暂停节点更新，1280×747 | 2.55 ms | 1.62 ms | 4.99 ms |

降低分辨率明显缩短 GPU 时间，却未改善战斗总帧耗时。静止场景的绘制成本低于 120 FPS 的 8.33 ms 预算；CPU 更新才是本组样本的主要瓶颈。冻结世界是诊断操作，不能当成可玩的游戏性能，也不能由此保证复杂弹幕稳 120。

独立组件取样同样发现动态角色阴影、敌人更新和弹丸步进都有开销。六卡阶段世界本身物理回调平均占每显示帧约 4.51 ms（其中弹丸约 3.00 ms），角色阴影约 2.5 ms／帧，敌人脚本约 3.3 ms／帧。这些为 CPU 局部测量，未覆盖所有子节点、引擎物理与渲染提交；不能直接相加得出全部帧耗时。慢帧又会触发更多物理补步：240 个显示帧执行约 537 次物理更新，进一步放大卡顿。

后续应以保留外观为前提处理 CPU：先查剩余子节点／引擎更新、削除重复工作，再重整弹丸密集循环、碰撞提交、AI 查询与动态阴影更新。不要重复开启 111 中已经测出无稳定收益的 GDScript 空间格子；也不应先砍草、树、灯光来掩盖逻辑瓶颈。先做到正常战斗稳定 60，再验证高强度弹幕和 120 目标；本版不宣称实现新的帧率提升。

## 复现资料

- `scripts/world/speech112_probe.gd`：实际场景气泡、队列、锚点、重开、选卡、最终奖励、离场与超时验证；结果见 `speech112-validation.json`，截图见 `captures/world_restart/speech112_single.png`、`speech112_second.png`。
- `scripts/world/combat112_profile.gd`：上述分辨率／冻结对照；原始数据 `combat112-profile.json`、日志 `combat112-profile.log`。
- `scripts/world/combat112_components.gd`：组件 CPU 取样，日志 `combat112-components.log`。这组继承探针未开启 GPU 计时，因此其中 GPU=0 表示未采集，不表示免费渲染。
- `Performance.TIME_PROCESS` 等采样值可能跨阶段保留旧值，冻结阶段尤其明显；表中总帧耗时来自逐帧实际计时，GPU 时间来自 RenderingServer 的 viewport GPU 计时。

本次没有降低分辨率、阴影品质、草树密度或修改生产版伤害／弹丸上限。低分辨率和冻结仅在独立诊断进程使用。
