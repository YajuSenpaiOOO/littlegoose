# 84：静态构建缓存、小站接地与石面

2026-10-20。用户反馈启动很慢、候车厅似乎浮空、花坛和苔石踏面仍像便宜3D、楼梯后面有未覆盖石材的切面。

## 启动测量与处理

不是三维场景必须等两分钟。本项目此前用于连续试验，启动时每次生成树根贴地网格、草地布局、地形和碰撞等，还重复生成了两轮树根。83基线探针在本机约132.40秒：两轮树根几何68.15秒、地形22.32秒、草地布局14.21秒、树根遮罩约2.16秒；其余为其他初始化及等待。这些是分段累计，部分段有嵌套，不能当成完全独立的加总。

84保留运行时组织与互动逻辑，把静态结果预存到assets/bake84：

- 地形ArrayMesh及对应分块/道路段索引；加载后仍创建原三角网格碰撞和floor_tiles查询。
- 树根网格、裁切位置、下沉量与碰撞中心偏移。键包含源贴图哈希、原图轮廓参数、位置、高度、地形状态等。
- 草地筛选布局/颜色，以及CPU计算的最终贴地Transform3D。不把无窗口渲染器的空GPU缓冲当成有效数据。
- 地理脚本继承链、道路JSON、岸线遮罩与相关脚本内容进入依赖指纹；地形/道路变化时重新生成。移动station_layout83里的厅/花坛等摆位标记不会触发全图重烘焙。

最终完整命中探针16.84秒，terrain/grass/grass_pose均命中，907次树根请求命中、0次重建；同机无窗口探针与83基线比较，场景构建耗时约减少87%。记录在startup84-baseline.json、startup84-warm-measurement.json及cache84-warm-final.log。真实窗口另有资源/着色器/窗口初始化，不承诺任意电脑固定16.84秒，也不是战斗帧率基准。

缓存已在本轮生成，正常启动直接使用。缺失或相关源数据变化后的首次重建仍较慢。当前是开发工程缓存方案；发布导出仍需把预烘焙数据与资源清单纳入正式打包流程。开发期间旧指纹文件暂保留，加载器只选择当前指纹对应的数据，不把旧数据用于新地形。--no-startup-cache84可作无缓存对照，默认不要开启。

## 候车厅

原二维厅图的两根前景木脚比墙基低，之前按木脚最底824像素定位，使整排石基实际离地；厅后移后这点更明显。84改按795像素石基底边落位，低出的木脚自然被铺装遮住，没有整体降低建筑碰撞/窗光或改动手调锚点。编辑器中的厅预览同步锚点。

原投影接收面是原地形+0.024m，但广场铺装高于它，投影会被砖面盖住。84重建后将接地投影抬至铺装上方约0.03m，保留原随太阳方向的轮廓。没有用更强全身发光去掩盖接地问题。

## 石阶与花坛

侧阶附近残余的原地形面也按局部区域+坡度接收手绘挡墙石材，避免仅给新增墙网格材质而漏掉相邻坡肩。范围局限在阶口，不把整张地图变成苔石。

首轮试验把墙面贴到踏面会太碎，最终另生成平静石灰岩顶面assets/stone84/painted_limestone_top84.png，配独立踏面分缝和小幅石板色差；立面继续用原手绘苔石，降低夸张饱和与大面积绿色页岩感。新顶面经内置image_gen生成，源文件、完整最终提示词见[生成记录](../assets/stone84/generation.md)，没有覆盖旧素材。

花坛把长直方体石框改为略有高低/进退变化的低矮石块，保持一个网格批次，沿用已有花草/苔色内床。碰撞范围与手调标记仍保留。画风效果待用户判断，当前仍是手绘贴图结合几何，并非整件重新画成立牌。
