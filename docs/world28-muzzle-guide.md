# 连续世界 28：枪口弹道线与精确射击对照

2026-10-17。默认启动器使用 world28；`preview_world_combat26.cmd` 保留之前的对照场景。

## 目的与操作

把瞄准提示、原随机散布和命中后的反馈分开对照。本轮没有再增强闪光、震动或顿帧，也没有加入强制锁定或改动 Shift 奔跑。

- `E`：枪口辅助线 → 原地影 → 关闭辅助，仍保留鼠标指向的准星。
- `Z`：精确直射（默认）→ 原 ±0.025 弧度散布，约 ±1.43°。有散布时显示两侧范围线。
- `F6`：沿用新身体射线／旧中心辅助对照。
- 其它按键沿用 world26。

枪口线从小黑鹅当前可见的插值后枪口出发，不使用主角位置。点线表示中心弹道：命中怪物变浅绿，碰到地形、墙和树干提前终止并变橙色，终点处显示小点。提示长度受实际弹速与寿命决定的射程约束。弹丸仍真实飞行、仍有飞行时间；没有变成即时点击伤害。

## 已确认的因素

旧普通攻击存在 ±1.43° 的随机散布。world24 新增一个可覆写的散布角度方法，默认返回原值；只有 world28 的精确对照默认归零，`Z` 可恢复。

八个屏幕方向的实际发射测试表明，精确模式中的三维弹道投影都对着鼠标，未测到斜角方向映射错误。同样的世界弹速在 25° 透视下投影速度不同：本次同一位置测得左右约 1008–1019 像素/秒，纵向约 441–475，四个斜向约 553–637。该数值只代表这次相机与目标位置的局部投影，不代表整个地图固定比率。

这说明透视速度差异是确实存在的感知因素，但不能直接证明它就是玩家觉得奇怪的唯一原因。当前未按屏幕方向修改子弹速度或射程；若辅助线和去散布后仍别扭，再单独比较屏幕速度补偿或较高的战斗镜头。

## 小黑鹅 buff 与可选锁定

目标位置与发射位置保持分离，后续小黑鹅离开主角时，枪口线仍随它移动；本轮测试直接平移小黑鹅超过两米验证了这一点。尚未实现完整追鼠标 buff。若未来小黑鹅能飞到鼠标位置，需要规定到达后的开火朝向或最小距离，避免目标和枪口重合。

锁定可以作为可选的目标选择方式，不应成为修补坐标或反馈问题的必要操作。以后加入时，仍可复用“选取目标 → 从当前小黑鹅枪口发射”的接口；需要另外定义目标死亡、遮挡、离开射程、切换目标和 buff 是否改变目标选择规则。Shift 已用于奔跑，不能直接叠加锁定。

## 验证

`aim28_probe.gd` 的 26 项检查通过，覆盖八方向三维与屏幕投影一致性、真实子弹命中、精确／散布切换、离体小黑鹅枪口、实体墙截断及颜色、三档辅助模式，以及实际 GPU 像素输出。原攻击链 `combat24_probe.gd` 回归 29 项通过。

显示位置使用 `get_global_transform_interpolated()` 读取可见小黑鹅的枪口，而发射判定仍使用物理帧位置，符合 [Godot 对可见插值位置的说明](https://docs.godotengine.org/en/stable/tutorials/physics/interpolation/advanced_physics_interpolation.html)。高速运动下二者仍可能存在一个物理帧以内的差异，尚未重写整个镜头插值系统。
