# NativeCombat113

Windows x86_64 GDExtension for the projectile hot loop. It retains the existing data pool, Jolt segment-ray collision, immediate GDScript damage callbacks, 30 Hz steering, 60 Hz flight and deferred 6/4 fragment creation. Other platforms use the script path. This is not a replacement physics engine or an active-projectile limit.

## Rebuild

- Engine API: generated by the installed Godot 4.7.2 stable (`ed1daf0bf`).
- godot-cpp MIT source: [cedbd9e71b24eb2898b28867c5faf6114da9e5e2](https://github.com/godotengine/godot-cpp/tree/cedbd9e71b24eb2898b28867c5faf6114da9e5e2).
- Downloaded godot-cpp archive SHA256: `6c2b4015a2b34af26e2a20dfedb73cd87ef75b12ab649ab8b6bbbb154190267e`.
- Zig 0.13.0 Windows x86_64, official archive SHA256: `d859994725ef9402381e557c60bb57497215682e355204d754ee3df75ee3c158`.
- Built DLL SHA256: `662aec2f05c02d25553e4fc8133cc191e709c965a83b0f56d99e967a694f0af7`.

From the workspace root, with dependencies in `.tmpwork/native113`:

```powershell
D:/work/python/python.exe tools/build_combat113.py --zig .tmpwork/native113/zig-windows-x86_64-0.13.0/zig.exe --godot-cpp .tmpwork/native113/godot-cpp-master --engine D:/work/Agent/Godot_v4.7.2-stable_win64/Godot_v4.7.2-stable_win64_console.exe --jobs 4
```

Close processes that loaded the DLL before rebuilding. Compiler and generated binding files stay outside the game. The DLL includes the needed C++ runtime. `GODOT_CPP_LICENSE.md` accompanies the binary.

## Verification

`native113_unit.gd` checks 100 movements/retirements in a minimal native world. `combat113_probe.gd` checks 47 actual combat behaviors. `combat113_visual_probe.gd` compares 200 tracked projectiles over 40 ticks against the script path, then tests terrain, effects and pace switching. `combat113_native_compare.gd` alternates script/native/native/script in one loaded scene; final whole-version measurements are in `docs/combat113-final-comparison.json`.

Set `use_native113=false` for the script fallback. The visual test can run both paths in the same scene. The native helper never owns scene lifecycle or enemy pointers between calls.
